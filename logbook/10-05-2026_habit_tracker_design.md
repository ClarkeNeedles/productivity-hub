## Summary of Changes
* **BaseModuleCard Reversion:** Changed the `BaseModuleCard` component back to a class implementation for the time being.
* **Infinite Creation Loop Fix:** Resolved a critical bug when instantiating a module from the `AddModuleModule` that was triggering an infinite rendering/creation loop.
* **Isolated Data Pass:** Modified `ModulePreviewCard` to ensure it only receives a temporary cloned copy of a module rather than a direct reference.
* **Optimized State Selector Usage:** Restricted access to the `activeModules` class object instances to areas where the actual class methods or properties are strictly required (e.g., passing it to `ModuleCardFrame`). 
  * *Refactor:* Everywhere else, implemented a pattern using `activeModuleIds` alongside a `getActiveModule(id)` lookup utility to reduce unnecessary re-renders.
* **Default Module Injection:** Hardcoded the configuration so the `AddModuleModule` is officially and exclusively generated by default at compile-time directly inside the `modules.ts` store file.
